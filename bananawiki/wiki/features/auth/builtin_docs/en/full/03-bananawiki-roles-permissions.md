# Roles and permissions

Every account has one role. Administrators can add custom roles, per-account permissions and category restrictions on top.

## Built-in roles

| Role | Access |
|---|---|
| **User** | read pages; create pages, boards and canvases and work on their own; propose changes to other pages |
| **Editor** | also edit every page, board and canvas they can open, and manage categories |
| **Administrator** | manage accounts, settings, features and all content |
| **Owner** | administrator that other administrators cannot change |

A superuser is an account that only other superusers can change. The account created when the wiki is set up is an owner and a superuser.

## Custom roles

**Administration → Roles** shows what everyone with the role User or Editor may do; administrators can change it for the whole wiki. A custom role is a named set of permissions and category rules on a base role, for example **Support editor** or **Course assistant**; it replaces the base role's defaults for the people who have it.

## Per-user permissions

Administrators can change single permissions for one account, on top of its role or custom role: the rest keeps following the role. The account's page shows **What <name> can do** in a few lines. When several people need the same access, a custom role is easier to keep track of.

## Category restrictions

Permissions say *what* someone can do; category restrictions say *where*. Together they let someone edit one category and only read another.

## Asking for edit access

If an administrator switched it on (**Administration → Access requests**), a page you can read but not edit shows **Ask for edit access** where the Edit button would be. You ask to edit pages in the page's category, or pages in general, with a short message if you like. An administrator approves or declines, and you get a notice either way. Elsewhere, the wiki tells you why you cannot edit something; boards and canvases name the person who can share them with you.

## Reviewing access

Give each person the smallest role that works, and check the list of owners and superusers from time to time.
