# Easy Deployment App

The Easy Deployment App is a portable desktop launcher for people who need
BananaWiki at work but do not want to install or administer a server. The
source lives in `easy_deployment_app/`, it is packaged with
`easy_deployment_app/bananawiki_easy_deployment.spec` (PyInstaller), and
`.github/workflows/easy-deployment-app.yml` builds the executables.

It runs one standalone BananaWiki instance on the user's computer. It does not
run the multi-tenant hosting platform.

## What it does

- Ships one executable per platform: Windows, Linux, and macOS.
- Requires no separate Python, nginx, systemd, or database installation.
- Creates a `bananawiki` folder beside the executable.
- Keeps all content and session-signing data in that folder.
- Shows whether the computer is connected to a network, without requiring
  internet access.
- Provides Start, Stop, Open BananaWiki, and Open Files Folder actions.
- Detects previous BananaWiki data on later starts.
- Shares a classroom or offline lab instance over the local WiFi/LAN.
- Shows a QR code and copyable address for student devices.

## How It Works

The GUI launches itself in a hidden server-child mode. The child imports the
normal BananaWiki Flask app and sets these environment variables:

| Variable | Portable path |
| --- | --- |
| `BW_INSTANCE_DIR` | `bananawiki/instance` |
| `BW_DATABASE_PATH` | `bananawiki/instance/bananawiki.db` |
| `BW_UPLOAD_FOLDER` | `bananawiki/uploads` |
| `BW_ATTACHMENT_FOLDER` | `bananawiki/attachments` |
| `BW_CHAT_ATTACHMENT_FOLDER` | `bananawiki/chat_attachments` |
| `BW_KANBAN_ATTACHMENT_FOLDER` | `bananawiki/kanban_attachments` |
| `BW_CUSTOM_PAGE_FILES_FOLDER` | `bananawiki/custom_page_files` |
| `BW_FAVICON_UPLOAD_FOLDER` | `bananawiki/favicons` |
| `BW_TTS_FOLDER` | `bananawiki/tts` |
| `BW_LOG_FILE` | `bananawiki/logs/bananawiki.log` |

Because `BW_INSTANCE_DIR` contains `.secret_key`, browser sessions remain valid
as long as the `bananawiki` folder is kept.

## Data Management

The app provides **Export All**, **Import**, and **Delete All** buttons in the
GUI (server must be stopped first).

- **Export All** creates a unified BananaWiki archive ZIP containing the raw
  SQLite database and all runtime assets (uploads, attachments, etc.). The
  archive is compatible with the hosting platform's import and the standalone
  wiki's Settings → Migration → Import.
- **Import** accepts a ZIP archive (from any source: hosting platform download,
  standalone export, or another easy-deployment instance). It **deletes all
  current data** and replaces it with the contents of the archive.
- **Delete All** wipes all pages, uploads, and settings while preserving the
  `.secret_key` so existing browser sessions remain valid.

## Internet Detection

The app checks for internet connectivity on startup by trying to reach common
DNS servers (1.1.1.1, 8.8.8.8, 208.67.222.222). If it detects no internet, the
UI shows a warning banner.

## Port Selection

The app first tries port 80 for a simpler URL (no port number required). If
port 80 is unavailable (privileged on most systems) or already in use, it falls
back to port 1234, then 1235, 1236, etc.

## Offline Labs

The app is intended to work when the internet is unstable or unavailable. It
only needs a local network if other devices must connect.

Supported modes:

| Mode | Address shown |
| --- | --- |
| Computer only | `http://127.0.0.1:PORT/` |
| Classroom network | `http://LAN-IP:PORT/` for student devices, plus `127.0.0.1` for the host computer |

For a classroom, the teacher can connect the host computer and student devices
to the same router, travel router, or phone hotspot. The hotspot/router does
not need internet access as long as devices can see each other on the local
network.

Operating systems may show a firewall prompt the first time the app allows
network access. The teacher should allow access on the private/local network.

When classroom network mode is active, the app shows a QR code for the student
address and a **Copy Address** button. Students still need to be connected to
the same local network; the QR code is just a shortcut to the LAN URL.

## Build

Build on each target operating system:

```bash
python -m pip install -r requirements.txt pyinstaller
python scripts/build_easy_deployment.py
```

The build script creates the user-facing portable artifact in
`easy_deployment_app/dist/`:

| Platform | Portable artifact |
| --- | --- |
| Windows x86_64 | `BananaWikiEasyDeployment.exe` |
| Linux x86_64 | `BananaWikiEasyDeployment-linux-x86_64.tar.gz` |
| macOS arm64 | `BananaWikiEasyDeployment-macos-arm64.zip` containing `BananaWiki Easy Deployment.app` |

Do not upload the raw Linux executable or raw macOS `.app` directory as release
artifacts. Some artifact systems strip Unix executable bits from uploaded
files, which makes the downloaded Linux binary or `.app/Contents/MacOS`
launcher non-runnable. Upload the archive generated by the build script
instead.

PyInstaller should be run natively for each target:

- Windows x86_64 build on Windows.
- Linux x86_64 build on Linux.
- macOS arm64 build on Apple Silicon macOS.

The GitHub Actions workflow at
`.github/workflows/easy-deployment-app.yml` builds the three release artifacts
on native runners.

## Current Limitations

- The first release artifacts still need real classroom smoke tests on Windows,
  Linux, and macOS.
- Some school networks block device-to-device traffic. In that case, use a
  simple local router/hotspot dedicated to the lab.
- Production signing/notarization is still needed for smooth Windows/macOS
  trust prompts.
- Final release builds must be smoke-tested on each target OS.
